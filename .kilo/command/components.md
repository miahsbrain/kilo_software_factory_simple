---
description: Build or refine reusable components needed by the frontend flow
---

If an app has an existing style, ask whether to keep it or do a complete redesign unless the user already specified the direction. Develop reusable components before screens using Tailwind CSS or a supported, stack-compatible UI library such as shadcn/ui, styled to the chosen visual language and theme. Do not limit choices to libraries already installed; obtain authorization before new dependency installation. Reuse suitable components without preserving unwanted styling and cover relevant interaction/accessibility states. Present the initial component gallery, ask whether the user wants unslop, and run focused QA regardless. Have the builder fix meaningful findings and recheck, then compose screens from those same components. Do not require a new gallery for every screen. Present the frontend flow for user approval before backend implementation; label fixtures clearly.
