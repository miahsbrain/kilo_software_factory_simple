description: Bootstrap services or restore ignored local tooling

The user-chosen workspace is the boundary. Check CWD/source/resolved project destination and resolved control/app/worktree targets against the user's selection before creation or writes; stop on mismatch. Never infer destinations from product display/service names, enter siblings or reuse unrelated board/worktree paths without explicit approval. Project CWD must equal source factory root; relative destinations use CWD. Default is local `project/`, custom destinations must stay within the factory unless the user explicitly approves an external path first, then use `--allow-outside`. This flag is capability, not consent, and is invalid for app/restore. Restore's explicit external target remains supported without it; verify the approved clone.

Use the deterministic CLI, never manual copying. From the factory root run `python3 .kilo/skills/git-worktree/scripts/bootstrap.py project` (default `project/`), or provide a factory-local `--destination <new-path>`. Project Git is mandatory. Services live under `project/apps/<service-name>`: any number of frontends, backend variants, workers or cronjobs, not fixed role slots. Use meaningful product-role names such as `shop-frontend`, `shop-backend`, `billing-worker`, `inventory-cron`; lowercase kebab-case permits arbitrary meaningful roles. ASK for a meaningful name if unclear and ASK separate app Git versus project tracking unless already specified. From the initialized control root run `python3 .kilo/skills/git-worktree/scripts/bootstrap.py app <service-name> --git separate|project`. No ownership default.

Both modes preserve source/docs and ignore clone-local harness/config/devcontainer/generated root instructions/live board/secrets/outputs. `services.json` is the single tracked control manifest (name, path, separate/project ownership); `.kilo/repos.json` is generated with control plus separate services only. Separate services get a safe ignore snapshot and one initial commit. Integrated services get the same ignores and a targeted control unignore, no nested Git/staging/control commit. Existing apps are not updated by later ignore edits.

For a fresh clone invoke the factory checkout's script: `python3 /path/to/factory/.kilo/skills/git-worktree/scripts/bootstrap.py restore --destination /path/to/project`. Clone separate services yourself into registered `apps/<service-name>` paths, then restore each with `restore --destination /path/to/project/apps/shop-frontend --project /path/to/project`. Restore control first; app tooling inherits it. No network, Git init/add/commit, source edits or overwrites. Missing files restored, identical left, any conflict refused before writes; no force flag. Missing checkouts are reported, not fabricated.

Restore refuses tracked output paths and all tracked ancestors before tooling/exclude writes. App restore creates no app-local devcontainer: open the control project folder in its devcontainer, then work under `apps/<name>`. Service instructions use relative `../../` context and lifecycle ancestor discovery, not host-absolute pointers; mounted control config supplies `KILO_CONFIG`. Existing app devcontainers remain untouched, not endorsed. Separate-app bootstrap checks hard init/add/commit denials in both source and target-control policies; allowances never override the other's denial.

Read `README.md` for constraints. User authorization covers exactly one initial source commit only in genuinely new project/separate-service repos created by the invocation. The narrow protected-branch/worktree bootstrap exception does not weaken policy, bypass hard command denials or skip hooks; honor existing identity. Existing destinations are refused. Identity preflight failure creates nothing; later failures retain partial state for inspection. No installs/scaffolding/existing-repo commits. Feature implementation waits for the initial commit and assigned worktree.
